# Q3 lane report: linear baseline and metrics

## What was built

**Keyword rules (own commit, `0b309e3`, before any model result)**

- `config/keywords.toml`: the whole linear rule set, with a version, ten
  component groups, a generic fallback and a broad safety phrase list.
- `src/field_quality_agents/baseline/keywords.py`: typed loader and
  deterministic matcher. Whole-token matching only, component hits weighted
  3× narrative hits, specificity by score, ties to the earlier group, fallback
  considered only when nothing specific matches, no match → `unclear`.
- `tests/baseline/test_keywords.py`: group-by-group component checks, fallback
  behaviour, whole-token boundaries, tie order, safety phrases, validation
  errors. The keyword commit contains no model code and no results.

**The "before" pipeline** (`baseline/pipeline.py`)

- `run_linear(cases, keywords)` registers each `Case` (the input object), sorts
  it with the keyword rules, raises the keyword safety flag, routes safety to
  `priority` and everything else to `standard_test`, and closes every
  standard-test case as `closed_no_trouble_found` because the simulated test
  always passes. `BaselineDecision` matches `docs/INTERFACES.md` §Q3.
- It never reads `case.group` or `case.safety_relevant`; a test sets both to
  the opposite of the report text to prove the truth fields cannot leak.
- `baseline_runs` wraps decisions as Q5 `CaseRun` records with a four-step
  synthetic trace, so the shared workload metric sees one shape from both
  pipelines.

**TF-IDF + logistic regression reference** (`baseline/tfidf.py`)

- `fit_tfidf_logreg` / `run_tfidf_logreg`: narrative-only TF-IDF (word 1–2
  grams, `min_df=2`, 50,000-feature cap, sublinear TF) and multinomial logistic
  regression (`lbfgs`, `C=2.0`, seed 20261031). It trains on the 2020–2024
  knowledge base and predicts the 2025 replay set, a time split rather than a
  random one. Narrative-only is deliberate: a reference that also read the
  NHTSA component string would mostly relearn the taxonomy.

**Every PLAN §7 metric as a pure function** (`metrics/`)

| PLAN §7 area | Functions |
|---|---|
| Component group | `macro_f1` (2,000-resample percentile bootstrap, seeded `rng`), `group_coverage` (Wilson) |
| Safety | `safety_scores` → precision and recall with Wilson intervals |
| Evidence | `quote_grounding`, `citation_validity` (id exists and quote found in that source, re-checked rather than trusting `verified`) |
| Test decision | `targeted_test_share`, `targeted_test_with_quote_share` |
| Issue detection | `issue_detection` → early share, median lead days, random-week base rate with a seeded `rng` |
| Recall linking | `recall_link_match_rate` |
| Workload | `workload` → human touches, decided without edits, steps, cost per 1,000, latency p50/p95, budget hits |
| Before vs after | `compare` → 19 fixed rows with deltas and direction notes |

The helpers in `metrics/estimates.py` hold rounding, Wilson and percentile
arithmetic. No metric reads a file, calls a model or uses unseeded randomness.

**Runner and CLI**

- `baseline/runner.py` reads `data/replay_2025.parquet` and
  `data/kb_complaints.parquet`, runs the pipeline and reference, and writes
  `results/baseline/{decisions.json,metrics.json,tfidf.json,SUMMARY.md}` with
  sorted keys and no timestamp.
- `fqa baseline` (and therefore `make baseline`) now runs it; optional flags
  `--data-dir`, `--out-dir` and `--keywords` exist for fixtures.

## Results committed in `results/baseline/`

- 600 replay cases; 299 routed to priority, 301 to the standard test, 301
  closed as no trouble found.
- Keyword component sort: macro-F1 **0.7340** [0.6870, 0.7691], coverage
  **1.0000** [0.9936, 1.0000]. The most common error is
  `electrical_general` → `power_and_wiring` (36 cases).
- Keyword safety flag: precision **0.4482** [0.3928, 0.5048], recall **0.8590**
  [0.7957, 0.9050] against the crash/fire/injury/death flag. The broad flag
  deliberately over-routes; that is the "before" behaviour the project
  measures.
- TF-IDF reference: accuracy 0.6917, macro-F1 **0.4978** [0.4383, 0.5489] on
  the 600-case test set, trained on 40,000 cases with a 50,000-term vocabulary.
- Two consecutive `make baseline` runs were byte-identical (all four files,
  compared by sha256).

## How tested

- `tests/metrics/` (hand-computed fixtures): macro-F1 from per-label counts,
  2/3 and 4/5 → 0.7333; `unclear` counted wrong; coverage; Wilson precision
  0.5 and recall 1/3 with closed-form bounds; citation validity ignoring a
  stale flag and honouring whitespace normalisation; targeted-test shares;
  recall-link matching on four fields; issue precision 0.5, median lead 61
  days and base rate 0.5 on a one-week fixture; workload 1.5 touches, 0.5
  unedited, 30 USD per 1,000, p50 80 ms, p95 98 ms; comparison rows and deltas.
- `tests/baseline/`: keyword rules, routing and NTF close, truth-field leakage
  guard, synthetic trace shape, TF-IDF separability and determinism, and an
  end-to-end runner over a fixture parquet that checks output names, stable
  bytes and parsed contents.
- Commands run: `make baseline` (twice, byte-identical), `make test`
  (268 passed), `make lint`, `make typecheck`, `make scan-forbidden`,
  `make scan-secrets`.

## Deviations and shared-file changes

- **`pyproject.toml` + `uv.lock`**: added `scikit-learn` (with numpy/scipy) for
  the reference model, and a mypy override because scikit-learn ships no type
  information. This is the only new runtime dependency.
- **`src/field_quality_agents/cli.py` and `tests/test_cli.py`**: `baseline` is
  no longer a stub. The stub test now uses `issues` (still Q8) and a new parser
  test covers the baseline flags.
- **Modelled workload**: the linear pipeline gets one human touch per case
  (registration and release), four fixed steps, zero cost and zero latency.
  This is a documented model in `baseline/pipeline.py`, not an observed run.
- **Not-applicable metrics** are left `None` in the baseline `Metrics`: quote
  grounding, citation validity, issue detection and recall linking. The linear
  pipeline has no quotes, issue agent or recall linker.
- **TF-IDF uses the narrative only**, so it is not a like-for-like replacement
  for the keyword component sort; it is the second reference the plan asks for.
