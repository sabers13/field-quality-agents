# Q14 lane report: final live test on unseen data

Branch: `fm/fqa-q14` (local only; nothing pushed, no remote, no PR).

## What changed

- **Unsealed and ran `final_live`.** The deterministic linear baseline was
  rerun on the 150 cases into `results/final-live/baseline/`; the agentic desk
  ran live in record mode as `final-live` into `results/final-live/`, with 174
  turns under `recordings/final-live/`. The run request is clean
  (`model_input: clean`): PLAN §7's group and safety labels never reached the
  model.
- **Set support in the pipeline.** `RunSource.cases(set_name)` now reads any
  committed `<set>.parquet`; `execute_run` passes its `set_name` through.
  `run_baseline(case_set=...)` and `fqa baseline --set` do the same for the
  linear pipeline. The existing replay path is unchanged.
- **Make targets:** `baseline-final`, `run-live-final` (guarded by
  `FQA_LIVE_APPROVED=1`) and `serve-live` (live dashboard over the Q14 run).
- **Final live panel.** `api.models.CommandCentreData` gains an optional
  `final_live` field (`FinalLiveData`/`FinalLiveSide`); `build_command_centre`
  passes it through; `export/final_live.py` reads
  `results/final-live/metrics.json`, its manifest, and the exported run's
  metrics. `fqa export` writes it into `data/command_centre.json` and the
  bundle; the API serves it from `/api/kpis` in both replay and live mode.
  `web/src/components/FinalLivePanel.tsx` renders it on the command centre,
  with `web/src/lib/finalLive.ts` building the rows and a unit test.
  `docs/INTERFACES.md` records the additive shape.
- **Proof:** `results/final-live/playwright/` (14 screenshots and `replay.gif`),
  `reports/FINAL-LIVE.md`.

Shared files touched, deliberately small: `Makefile` (targets),
`docs/INTERFACES.md` (additive field), `api/{app,deps,kpis,models,reports}.py`,
`run/{data,dashboard,live,pipeline}.py`, `baseline/runner.py`, `cli.py`,
`export/site.py`, and the web types/panel. Every change is additive or a
parameter with the old default, so `make all`'s replay output is unchanged
apart from the new panel and the generalized baseline wording.

## Deviations

- **The group metric is a real measurement but a prompt defect.** The clean
  intake prompt p1 asks for a component group without listing the ten valid
  ids, so the desk answered with component text and macro-F1 is 0.0333. I did
  not change the prompt after looking at the sealed set: that would tune on the
  test cases and make the final live test meaningless. It is recorded as an
  open issue for a p2 prompt and a new run.
- **No prompt or method changes were made between Q9 and Q14** other than the
  Q13-reviewed clean payload, so the comparison isolates the new data (and the
  intake quote check Q13 added).
- The baseline summary wording was generalized from “the committed replay set”
  to “a committed case set” because the same code now runs on `final_live`.
  Numbers are unchanged.
- `reports/FINAL-LIVE.md` records the spend, numbers and findings.

## Open issues

1. Intake prompt p2 should name the ten group ids and describe what to do when
   the component is generic. Then rerun on a new unseen window; the current
   0.0333 should not be published as a capability score.
2. Safety over-flagging is the largest quality gap: 122 of 150 flagged,
   precision 0.1311. A prompt revision should separate “mentions a hazard” from
   “this report is safety-relevant”, and the safety row needs a second unseen
   test before it is stable prose.
3. Four weeks produced no fleet issue, so the issue metrics are blank for Q14.
   A longer window (or the Q9 year) is the right place to judge issue detection.
4. The targeted-test-with-quote share fell (0.4444 from 0.5636); the sample is
   9 proposals, so report the count, not a trend.
