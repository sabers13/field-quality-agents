# Q2 lane report: tools and MCP server

## What was built

**Typed tool layer** (`src/field_quality_agents/tools/`)

- `models.py`: `CaseFilters`, `SimilarCase`, `ClusterStats`,
  `QuoteVerification`, matching `docs/INTERFACES.md` §Q2.
- `db.py`: one process-wide `Toolbox` with a DuckDB connection over the
  committed parquet (`data/kb_complaints.parquet`, `recalls.parquet`,
  `investigations.parquet`, `events.parquet`, `fleet_weekly.parquet`, plus
  `replay_2025.parquet` for `cases`). It never reads `final_live.parquet`.
  `configure()` also accepts a fixture DuckDB file, which is what the tests and
  the MCP harness use. `FQA_DB` / `FQA_DATA_DIR` / `FQA_RULEBOOK` select the
  defaults.
- `search.py`: BM25 (`k1=1.2`, `b=0.75`) over a temporary DuckDB token table,
  with a small stopword list. Corpus statistics are computed over the filtered
  set; scores are rounded to 4 decimals before sorting, ties go to the lower
  id. The index is built once per connection (about 2 s for the real 40,000
  case knowledge base; queries answer in tens of milliseconds).
- `lookup.py`: `recalls_for` / `investigations_for` (exact make model year
  group, newest `open_date` first, then id; dates as ISO strings) and
  `case_lookup` over the knowledge base plus replay set.
- `cluster.py`: 27 weekly points (26-week trailing baseline plus the week
  containing `until_date`) with zero fill, trailing mean, and the PLAN §4
  spike rule. The threshold is the smallest count ≥ 3 whose Poisson upper tail
  is at most 0.1%, using the trailing mean floored at 0.5. `spike` is
  `observed >= threshold`.
- `quotes.py`: verbatim substring check after whitespace normalisation; case,
  punctuation and wording must match exactly.
- `rules.py`: `config/rulebook.toml` loader and whole-word/phrase matching for
  the seven example conditions (moisture, cold, heat, vibration, intermittent,
  after service, charging).

**MCP server** (`src/field_quality_agents/mcp_server.py`)

- `mcp = MCPServer("field-quality-agents")`, serving exactly the seven names in
  `docs/INTERFACES.md`: `similar_cases`, `recalls_for`, `investigations_for`,
  `cluster_stats`, `verify_quotes`, `rulebook`, `case_lookup`.
- JSON-compatible adapters convert dates, dataclasses and contract models.
  `filters` and `quotes` arrive as JSON objects; `until_date` is an ISO date
  string. Results are thin wrappers over the same functions the agents call.
- `fqa mcp` runs it over stdio. New flags `--data-dir`, `--db` and `--rulebook`
  select the source; with no flags the `FQA_*` environment is used. Stdout is
  never written to by tool code.

**Rulebook** (`config/rulebook.toml`)

- Example mapping: moisture → humidity/condensation, cold → low-temperature
  cycling, heat → high-temperature operation, vibration → vibration test,
  intermittent → long-run power cycling, after service → installation check,
  charging → electrical load test.

## How tested

`tests/tools/` (42 tests) runs against a small generated DuckDB built from
`tests/fixtures/tools_fixture.sql`; no committed data and no network:

- BM25 ordering, 4-decimal rounding, id tie-breaks, filters (including safety
  and case-insensitive matching), `k`, empty/stopword queries and excerpt
  truncation;
- recall/investigation sorting and filtering, case lookup fields and misses;
- cluster zero fill, consecutive weeks, spike/no-spike cases, midweek
  `until_date`, pre-series dates, and the Poisson threshold floor/monotonicity;
- quote verification (whitespace, case sensitivity, order);
- all seven rulebook mappings, synonyms, whole-word matching, multi-rule
  matches, invalid TOML, and the CLI `mcp` flag pass-through;
- an MCP client subprocess lists exactly the seven tools and calls every one,
  asserting payloads, including a null `case_lookup`.

Commands run:

- `make test`: 196 passed.
- `make lint`: Ruff clean.
- `make typecheck`: mypy strict clean on `src/`.
- `make scan-forbidden`: ok.
- `make scan-secrets`: ok.

A local smoke test also ran `similar_cases`, `case_lookup`, `recalls_for` and
`cluster_stats` against the committed `data/*.parquet` and returned sensible
results.

## Deviations and shared-file changes

- **BM25 without the DuckDB `fts` extension.** The notes describe the `fts`
  extension, but loading it on a fresh machine can trigger a network install,
  which would break the offline test guarantee. The search is still BM25 over
  DuckDB tables (document lengths plus postings in temporary tables). The
  trade-off is no Porter stemming; the stopword list is explicit and
  deterministic.
- **`pyproject.toml` + `uv.lock`:** added `mcp==2.3.0` (MIT), the official MCP
  Python SDK named in `docs/NOTES-mcp.md`.
- **`src/field_quality_agents/cli.py`:** the `mcp` command now dispatches to
  the server and accepts `--data-dir`, `--db`, `--rulebook`; the stub entry for
  `mcp` was removed.
- **`config/rulebook.toml`:** added; §Q2 names this file, although the ownership
  line lists only the tools package and MCP server.
- Recalls and investigations are sorted newest first because the interfaces do
  not name a sort key; this is documented in the docstrings.
- `cluster_stats.weekly` has 27 points so the 26-week baseline and the observed
  week are both present; the issue chart can show the threshold against the
  current point.
