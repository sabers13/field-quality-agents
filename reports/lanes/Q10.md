# Lane Q10: dashboard with real results and the static export

## What this lane did

- **Wired the recorded run into every page.** The static mode now loads the
  export's bundled run (`window.__FQA_BUNDLE__`, injected by
  `data/bundle.js`) and falls back to the Q6 fixtures only when no bundle is
  present (dev server, unit tests). No page keeps fixture numbers: the
  command centre, case board and detail, issue room and detail, before/after,
  replay and weekly report all read the 600-case `replay` run under
  `results/runs/replay/` (byte-identical to `live-2025`). The banner names the
  run and its counts; the offline export no longer offers Replay/Live modes
  because it has no API.
- **Fixed real-data formatting on the way.** KPI percent ids (`prepared_without_edits`,
  `ntf_without_evidence`) were multiplied by 100 twice, and `time_to_decision`
  printed its unit twice; the headline cards printed dollars as percentages.
  All now format in the metric's own unit, and lower-is-better metrics (cost,
  human touches) no longer show a green delta for getting worse. The fixture
  command centre was updated to the same API shapes.
- **Showcase examples by fixed rules** (`src/field_quality_agents/export/showcase.py`),
  computed from committed run files:
  1. **Earliest issue that preceded a fleet event**: the earliest opened issue
     with a linked recall or investigation dated within 365 days after it
     (PLAN §7's early-issue rule). In this run that is `I-20250711-002`,
     opened 2025-07-11, 66 days before recall `25V615000` (2025-09-15),
     shown on case `2102878`. No issue preceded an *investigation* in this
     snapshot — the two early issues preceded recalls — so the rule names both
     event types exactly as PLAN §7 does.
  2. **Longest agent trace ending in a targeted test**: case `2063828`,
     16 trace steps.
  3. **Linear no-trouble-found while the agent found a clue**: case
     `2052717`, where the agent verified a quotation and proposed a
     test after the linear pipeline closed the case.
  A fourth, reverse example (case `2052447`, linear right too) keeps the
  before/after page balanced and is labelled "Reverse:" so the page's
  existing split puts it in the right panel.
- **Built the offline static export** to `dist/field-quality-agents/`:
  `index.html`, `assets/`, the documented `data/*.json` files, plus
  `data/bundle.js` (8.4 MB) holding the same JSON so the page opens with no
  server and no network. The app is built as one IIFE and the export strips
  `type="module"`/`crossorigin` and defers the entry script, because browsers
  block ES modules on `file://`.
- **Screenshots** of all eight views (command centre, case board, case detail,
  issue room, issue detail, before/after, replay, weekly report) at 360 and
  1280 px, light and dark: 32 PNGs in `results/screenshots/`. They are taken
  against the static export served by a local file server, with case/issue ids
  read from the bundle itself.

## Deviations and open issues

- The task's first showcase rule says "preceded an investigation". No opened
  issue in this run preceded a linked investigation (the Fisker investigation
  predates its issue by a year; the Polestar and Tesla investigations opened
  one or two days before the issues). The rule therefore uses PLAN §7's
  definition, a matching recall *or* investigation following within 365 days,
  and names the event type in the text. This is the honest fixed rule for this
  data; the lane did not tune it after seeing the output.
- The export duplicates the data as both individual JSON files (for
  inspection and the reproducibility manifest) and one 8.4 MB `bundle.js`
  (for offline opening). `dist/` is generated and git-ignored; the committed
  evidence is `results/MANIFEST.sha256` and the screenshots.
- The weekly report page shows the latest week only (4 cases), because that is
  the newest `reports.json` entry; the full 53-week series stays in the run
  files.
- Q9's open issues (safety over-flagging, thin recall linking, the simulated
  engineer approving everything) are unchanged and still visible in the
  before/after numbers.
