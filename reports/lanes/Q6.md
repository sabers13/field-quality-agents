# Q6 lane report: dashboard frontend

## What was built

Every PLAN §6 page, against the fixture JSON shapes in `docs/INTERFACES.md`:

- **Command centre** — seven KPI tiles with sparklines and signed deltas, the
  agent-action feed with relative times, and a before/after mini comparison.
- **Case board** — six workflow columns (New, Intake, Analysis, Needs engineer,
  Decided, Issue-linked). Intake and analysis both use the "In agent" status
  tone and label per `docs/INTERFACES.md`, while remaining separate columns per
  PLAN §6 and DESIGN's six-column board. Search, group and safety filters.
  **Case detail** opens as a right sheet on desktop and full screen on phones:
  narrative with verified/unverified quote highlights, proposal and targeted
  test, evidence citations, decision panel, trace timeline with expandable raw
  JSON and copy, extraction, similar cases, linked recalls/investigations.
- **Issue room** — issue list, weekly cluster chart with the Poisson 99.9%
  threshold annotation, linked cases plus recall/investigation timeline, 8D
  D1–D4 draft, decision memo, citations that open a case or a recall dialog.
- **Before vs after** — headline deltas, all PLAN §7 metrics side by side with
  CIs, base-rate callout, and both example directions.
- **Replay** — run picker, play/pause/restart, 0.5×/1×/2×/4× speed, scrubber,
  revealed case statuses, event counts and a day-grouped event log.
- **Weekly report** — week counts, narrative, metrics table (definition-list
  layout on phones).

Data layer (`web/src/data/`):

- `DashboardDataSource` exactly as frozen in `docs/INTERFACES.md`.
- `LiveDataSource`: REST reads, decision `POST`, named SSE events with
  `Last-Event-ID` and connection events; injected `fetch`/`EventSource` for
  tests.
- `StaticDataSource`: bundled, cloned JSON with filtering, paging and typed
  not-found errors. It accepts any `StaticBundle`, so Q10's exporter can pass
  the real bundled run instead of the Q6 fixtures.
- Fixtures in `web/src/data/fixtures/` cover all six case statuses, two issues,
  full metrics/CIs, one replay run with 19 events, and fictional makes/models.
  A global banner labels static mode as bundled fixture data.

Shell and design:

- Responsive shell: 232 px rail at desktop, 64 px icon rail at tablet (labels
  visually hidden but still the accessible names), phone top bar with a page
  menu and five-item bottom navigation. Replay and weekly report are in the
  phone menu.
- Light/dark/auto theme with `data-theme` plus `prefers-color-scheme`; the
  ECharts wrapper follows the resolved theme.
- Focus-trapped, focus-restoring sheets and dialogs; keyboard-operable
  approve/override/ask; skip link; visible focus rings; status always carries
  a text label beside the dot.
- Charts are tree-shaken ECharts (line + grid + tooltip + mark line + canvas)
  and keep animation off for deterministic screenshots and reduced motion.

Playwright (`tests/web/`, config `web/playwright.config.ts`):

- `static.spec.ts`, `live.spec.ts`, `mobile.spec.ts`, `a11y.spec.ts`,
  `screenshots.spec.ts`. Live mode uses a mocked Q7 API (fixtures) including a
  decision POST; the SSE route returns 503 so the UI proves it keeps working
  while the stream reconnects.

## Deviations and shared-file changes

- **`docs/INTERFACES.md` gap:** the frozen `DashboardDataSource` has
  `getReplayRuns()` but no way to read a run's events, and no decision write
  method, although §Q7 documents both endpoints. Q6 adds two **optional,
  additive** members: `getReplayEvents?(runId)` and the separate
  `DecisionClient.submitDecision(...)`. Nothing required changed, so existing
  implementations still satisfy the interface.
- **Six columns vs the grouped "in agent" status:** `BOARD_COLUMNS` in
  `web/src/lib/status.ts` now exposes six entries so PLAN §6 and DESIGN's
  six-column board are met; both intake and analysis keep the "In agent" label
  and tone required by `docs/INTERFACES.md`. The Q0 status unit test was
  updated accordingly.
- **Light muted text token:** `--text-muted` changed from `#6f7c8a` to
  `#5f6c7a`. DESIGN requires WCAG AA in both themes; the original value gives
  3.76:1 on `--bg-subtle` and failed axe. The new value is 4.73:1 on the
  worst surface and is the only token value changed.
- **Additive signal:** `StreamEvent` (used by `CommandCentreData.live_feed`)
  was not defined in `docs/INTERFACES.md`; Q6 defines it as
  `{ id?, kind, at, data }` with the SSE event names plus a client-only
  `connection` kind for the live dot.
- **Dependencies:** added `@playwright/test` and `@axe-core/playwright` as web
  dev dependencies; no runtime dependency was added (ECharts/React were
  already in the scaffold).
- **`.gitignore`:** added `web/test-results/`, `web/playwright-report/` and
  `web/blob-report/`.
- **Test command shape:** the specs live in the repo-level `tests/web/` as the
  brief requires, outside the `web` npm package. `test:e2e` therefore sets
  `NODE_PATH="$PWD/node_modules"` so Node resolves `@playwright/test` from
  `web/node_modules`; the tests are run from `web/`. No root `package.json` was
  introduced.
- No backend, Makefile, contract, PLAN or design-file edits. No secrets, no
  real names, no remote, no push.
