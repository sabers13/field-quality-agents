# Lane Q11: docs

## What this lane did

- **`README.md`**: the plain question, the before/after picture, a three-step
  quickstart (`make setup`, `make all`, `make serve`), the headline before/after
  numbers with the two metrics files named, the run at a glance, the fixed
  comparison examples, screenshots, the dashboard pages and modes, the required
  limits, a repository map and the documents list. Every number comes from a
  committed file under `results/`.
- **`METHOD.md`**: PLAN §3–§8 in plain words — architecture, the desk and its
  agents, human checkpoints and hard rules, the data build, the dashboard, every
  metric and why it is measured that way, reproducibility, and what the method
  does not claim. It points at the code and the frozen plan rather than
  restating constants.
- **`THIRD_PARTY.md`** (polish): kept the NHTSA public-domain statement and the
  snapshot/PII wording, and added the model service, the direct Python and
  JavaScript dependencies with versions and licences, the development tools, the
  assets note (no downloaded fonts, icons or images) and attribution guidance.
  The PII section now states the screen's scope and points at the review finding
  that signature-style names are not covered.
- **`CHANGELOG.md`**: the first complete local version, 0.1.0 — what was added,
  the recorded run and its headline results, the changes that came out of the
  live attempts, the known limits.
- **`project-facts.yml`** and **`scripts/check_facts.py`**: the canonical facts
  file and a real check. Each headline row names its before and after source as
  `results/<file>#dotted.path`; each scalar fact names a JSON check. The script
  re-derives every value, requires the source to be tracked by git and under
  `results/`, cross-checks the record and replay manifests, the package and
  changelog versions, the README text (labels, formatted values, exact display
  strings, quickstart commands and sections), the document set and the screenshot
  inventory. The old no-op scaffold check is gone.
- Rebased onto `main` after the Q12 review landed. The README now marks the
  group, safety, routing and fleet figures as describing the committed run
  rather than an independent measurement, because the review found the component
  group and safety truth fields in the model input (B1/B2). The numbers are
  unchanged; the caveat is explicit.
- Corrected `results/MANIFEST.sha256` to the output of a clean `make all` (the
  review's B5), clarified the count in `reports/RUN.md`, and fixed the report's
  “trace steps” label to distinguish counted agent steps from trace records
  (S4).

## How it was tested

- `make facts`: green — 18 headline rows and 27 facts, each re-derived from
  `results/`.
- Negative test of the facts gate: mutating one headline value and one fact in
  memory produced exactly two failures and exit code 1.
- `make release-check`: green — Ruff, mypy on `src/`, 332 offline tests, the
  dashboard type-check and build, `scan-forbidden`, `scan-secrets`, `facts`.
- `make all` twice from a clean `dist/`: `results/MANIFEST.sha256` byte-identical
  (same sha256), `scripts/results_manifest.py check` green, and `git status`
  showed no change beyond the committed edits.
- `make scan-forbidden` and `make scan-secrets` on the staged tree.
- The facts check was run with and without `results/screenshots/`: absent, it
  reports the Q10 dependency as a note; present, it requires all 28 expected
  files.

## Shared-code touches (small, explained)

- `Makefile`: the `release-check` success line no longer says "on the Q0
  scaffold". No target behaviour changed.
- `pyproject.toml`, `uv.lock`: `pyyaml` added to the dev group. It was already
  installed transitively by `langchain-core`; declaring it makes the facts check
  independent of that accident.
- `results/MANIFEST.sha256`: regenerated from a clean build. The committed file
  had 16 extra entries for `dist/.../cases/C-2025-*.json` — leftover e2e fixture
  files in the git-ignored `dist/`, which a clean `make all` never writes. The
  clean manifest has 628 entries. `reports/RUN.md` now says so and explains why
  the Q9 session counted 644.
- `reports/RUN.md`: the “trace steps 2,542” label became “counted agent steps
  (budget counter)” with a separate “trace records 6,669” row, and the smoke
  table's 82 is labelled the same way (Q12 S4). No number changed.

## Open issues

- The review's B1/B2 fixes will re-score several rows of the headline table. If
  the fix changes `results/`, `project-facts.yml`, the README table and this
  lane's numbers must move together; `make facts` will fail until they do.
- The review's B4 (signature-style names in committed narratives) is a captain
  decision, not a docs edit. The documentation states the screen's real scope
  and points at the finding.
- `results/screenshots/` is Q10's deliverable and does not exist yet. The README
  embeds four deterministic screenshot filenames from the existing
  `tests/web/screenshots.spec.ts`; the facts check notes the missing directory
  now and will require the full 28-file inventory (seven pages × two widths ×
  two themes) once Q10 lands. If Q10 changes a page name, both the README and
  `project-facts.yml` must change together or `make facts` fails.
- The export writes into the existing `dist/field-quality-agents/data/` without
  removing stale files, which is how the old manifest picked up fixture cases.
  A clean `make all` is reproducible; clearing the export directory belongs to
  Q10/Q13 if they rework the export.
- `release-check` still does not run `scripts/results_manifest.py check` (Q12
  S8), because a check needs a preceding `make all`. The target exists and the
  clean tree passes it.
- The dashboard numbers were not re-read from a rendered page in this lane; they
  come from the same committed metrics the dashboard reads, and Q10/Q12 cover
  the rendered surface.
