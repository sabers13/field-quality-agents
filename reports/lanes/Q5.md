# Q5: agents graph

## What

LangGraph desk for one field-quality case, with the PLAN §4 hard rules in code.

- **`src/field_quality_agents/agents/graph.py`** builds the graph and runs a
  case. Nodes: `supervisor`, `intake`, `safety`, `analysis`, `budget`,
  `human_gate`, `finish`. `run_case` resumes every human checkpoint with the
  deterministic simulated engineer; `run_day` is the day seam Q8 will call.
- **Supervisor** routes on fixed policy: safety → human before analysis,
  missing extraction → intake, proposal → human, budget → human, decision →
  finish. Every routing choice is a `TraceStep` with its reason and prompt
  version. The graph is compiled with an `InMemorySaver` checkpointer by
  default, so `interrupt`/`Command(resume=...)` work out of the box.
- **Intake** asks the model for a normalised report, checks for duplicates via
  `similar_cases` within the same make/model/year, and drafts a `REQUEST_INFO`
  proposal when the model reports missing information or the answer is not
  readable JSON.
- **Analysis** calls `similar_cases`, `recalls_for`, `investigations_for`,
  `rulebook` and `verify_quotes` through the injected `ToolRegistry`, then asks
  the model for the proposal. Any clue whose quote fails verification is
  dropped before the proposal is built, so it can never become evidence.
- **Safety** builds a `SAFETY_PRIORITY` proposal in code when the case or the
  extraction is safety-relevant; it acts before any analysis tool runs.
- **Human checkpoint** suspends with `interrupt`. Approve/override of a test or
  safety proposal moves the case to `decided`; ask, request-info and any
  approval of a `REQUEST_INFO` proposal leave it at `needs_engineer`. The gate
  rejects a decision that names another case.
- **Budgets** are 12 steps and 40,000 tokens. The limit is checked at the
  supervisor; a case over either records `budget_exhausted` and goes to a human.
  Only model, tool and drafting actions count as steps; supervisor routing,
  human decisions and the finish bookkeeping are trace-only.
- **Trace**: every action appends a `TraceStep` with agent, action, reason,
  tool input/output, tokens, cost, duration and a contiguous step number.
- **Prompts** are versioned files under `prompts/<agent>/p1.md`;
  `load_prompt(agent, version)` validates names and returns the text, and each
  run records `p1` in `CaseRun.prompt_version` (supervisor reasons repeat it).
- **Simulated engineer** (`simulated_engineer.decide`) approves verified work
  and sends back unverified evidence, a targeted test without a verified quote,
  or a case without a proposal. It always acts as `SIMULATED_ENGINEER`.
- **Hard rules** are code, not prompts: safety-first routing, quote
  verification before evidence, and a `DecisionAction` set that has no close,
  scrap, return or charge action at all.

Public surface: `build_desk_graph`, `run_case`, `run_day`, `initial_state`,
`DeskState`, `CaseRun`, `ToolRegistry`, `load_prompt`, `decide`.

## How tested

`tests/agents/` (48 tests), all offline with a scripted fake model and a fake
tool registry:

- `test_branches.py`: targeted test with tools and verified evidence, safety
  reaches a human before analysis, missing information, budget hit, human
  override with an edited proposal, ask, unreadable intake answer, failing
  quotes dropped, safety found late by analysis.
- `test_hard_rules.py`: allowed action/status/proposal sets, no trace names a
  closing/scrapping/charging step, safety ordering, approved info request never
  decides, wrong-case decision rejected, unverified quotes never evidence.
- `test_property.py`: every branch plus a seeded 40-run random matrix of
  reports, proposals and engineer actions; a case is `decided` only with a
  human approve/override naming a decidable proposal, traces are contiguous and
  no case exceeds 12 counted steps.
- `test_simulated_engineer.py`: each deterministic decision.
- `test_prompts.py`: all `p1` prompts load, version/path validation, version on
  the run.
- `test_graph.py`: token accounting, contiguous trace, `initial_state` and the
  `run_day` boundary.

Commands run: `uv run pytest` (all green), `uv run ruff check .`,
`uv run mypy src`, `make scan-forbidden`, `make scan-secrets`.

## Deviations and shared-file changes

- **`pyproject.toml` + `uv.lock`**: added `langgraph==1.2.19`, which pulls
  `langchain-core` and the LangGraph checkpoint packages. The scaffold did not
  include LangGraph even though PLAN §4 needs it. This is the only shared file
  change.
- **Model seam**: `docs/INTERFACES.md` names Q4's `LangChainChatModel`. Q4 has
  not landed, so the graph depends on a two-method `AgentModel` protocol
  (`complete`). Q4's wrapper only needs a small adapter; tests use
  `ScriptedModel` and never touch the network.
- **Tool types**: Q2 has not landed, so `agents/tools.py` mirrors the Q2
  signatures (`CaseFilters`, `SimilarCase`, `QuoteVerification`,
  `ToolRegistry`). Q8 can pass Q2's module behind the same structural protocol
  or add a thin adapter.
- **`run_day`** runs the due cases and returns no issues; opening fleet issues
  from `cluster_stats` is Q8's issue agent, not Q5.
- **Simulated engineer send-back** is one shot: an `ask` records the decision
  and leaves the case at `needs_engineer` rather than looping a second
  proposal. The trace keeps everything needed for a retry loop later.

## Open issues

- The real Q4 adapter and Q2 tool registry are not wired yet; both are Q8 work.
- Checkpoint serialisation currently emits a LangGraph warning that the domain
  models are not in the msgpack allow-list. It does not change behaviour; Q8
  should register the contract types or use a JSON checkpointer for durable
  runs.
- Duplicate detection uses make/model/year/group similarity only; the
  close-date window from PLAN §4 belongs with the real `similar_cases` tool.
